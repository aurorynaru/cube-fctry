# Milestone B2 — offline texture QA

Run from the project root with the existing Python `Pillow`, `numpy`, and `jsonschema` packages:

```powershell
python tool/validate_texture.py workflows/textures/stone-seamless-v4.png --profile adventure-fantasy --seamless
python tool/validate_texture.py --batch workflows/textures/qa-batch.json --profile adventure-fantasy --seamless --dry-run
python tool/validate_texture.py outputs/wall.png --profile adventure-fantasy --request art/games/wall-request.json --expected-sha256 <64-lowercase-hex> --seamless
```

`--batch` reads a project-relative JSON array of project-relative image paths; positional arguments also accept multiple images. A single image may use `--request` (a v1.0 request JSON or `{"request": ...}`) or `--asset-id` (an existing B1-generated output). The CLI replays B1 first and validates the request against the unchanged v1.0 schema; any claimed pass/reviewer or QC/import/final approval in supplied request metadata is rejected. The CLI never calls `Registry.apply`. Without a request, required provenance/usage/delivery intent remains `REVIEW_REQUIRED`. Use `--seamless` for a tiling request. `--dry-run` writes nothing and emits reproducible JSON lines on stdout. Exit 0 means no detected hard failures (human review can still be required), 1 means one or more hard failures, 2 means a CLI/security/registry error.

Evidence is new-only under `registry/evidence/texture-qa/` (or `--out-dir`): a JSON report, Markdown assessment, native whole-tile 3×3 PNG preview for sources up to 1024×1024 (larger sources downsample to 256 px per tile), a 5×5 whole-tile preview downsampled to at most 256 px per tile, and a native-pixel center-cross crop (up to 512×512 px). The report states preview dimensions/policy. Source hashes, profile version/hash, validator version, dimensions, image/alpha mode, byte/memory estimates, budget comparison, raw edge/neighbor ratios, 8px-blurred edge means, and material texture proxies are in JSON. Re-running a non-dry evaluation of the same source requires a different `--out-dir` under `registry/evidence/` to preserve previous evidence. Create its parent directory first. No source image, schema, registry journal, or existing evidence is changed.

The raw edge screen uses the Milestone A proposed 1.25× limit on both axes. The blurred edge screen uses an 8-bit mean absolute RGB limit of 8 at radius 8 as a conservative *screening heuristic*, not a signed Art Bible criterion. SHA-256 is always recorded, but integrity is `REVIEW_REQUIRED` until an independent expected hash (CLI argument or B1 request deliverable hash) is supplied. Exact mathematical continuity is reported separately and is not required for visually acceptable joins. A broad-tone standard deviation above 6 **and** p99 deviation above 15 flags potential distinctive repeated motifs, but cannot detect every repetition. Genre proxy thresholds on high-frequency residual and broad-tone spread prioritize inspection of noisy or busy candidates; a quiet image does not automatically meet its genre. Neither favorable numerical screens nor a historical flat-image visual decision supplies a named B1 tiling/style/technical pass. Physical texture dimensions, UVs, compression, device FPS, content ownership, provenance truth, and identity of a reviewer need separate human/platform inspection.

Milestone B3 calls the same `texture_qa.evaluate`/`write_evidence` functions directly after a verified ComfyUI generation. It writes per-candidate evidence under `registry/evidence/texture-qa-b3/<request-id>/`, leaves all B1 gates pending and never treats `REVIEW_REQUIRED` as a pass. See `GENERATION_B3.md`.

All B1 gate entries in the output remain `pending` with empty evidence; the report itself is a project-relative evidence file eligible for later *human* QC submission. A QC reviewer must explicitly review and reference it (along with other required evidence) through the existing B1 CLI; B2 does not emit a `qc_passed` payload or approval. The prior original-stone FAIL and v4 flat-image PASS in `stone-texture-seam-review.md` and `workflows/textures/README.md` remain historical human observations, not B2-issued approvals.
